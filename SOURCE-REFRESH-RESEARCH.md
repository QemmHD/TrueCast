# TrueCast: source selection and refresh research

Reviewed 16 November 2026. This extends the broader provider comparison in [PLAN.md](PLAN.md) and the seven-app capability comparison in [COMPETITOR-RESEARCH.md](COMPETITOR-RESEARCH.md). Documentation and live endpoint checks establish capabilities, terms and integration behavior. They do not establish a worldwide forecast-accuracy winner.

## Recommendation

Keep **Open-Meteo best-match forecasts + CAMS air quality, RainViewer observed radar, and official NWS/NHC US/regional products** as the connected, personal noncommercial Pages stack. It provides useful regional model selection without exposing an API secret. Add independent official forecasts and recent quality-checked observations as separate comparisons, which this release implements for supported US locations.

**Xweather is the strongest next specialist integration candidate for lightning and broader hazard products.** Its current official API page advertises 15,000 free monthly accesses, no credit card and access to all API endpoints. This is more useful than describing it merely as a paid option. Account credentials, licensing, geographic coverage, access accounting and map-product entitlements still need checking before connecting it. The free API allowance is not a promise of unlimited map sessions or all WeatherBug features.

**Foreca is the most useful newly reviewed independent forecast benchmark for a personal free trial.** Its ongoing Freemium tier includes 2,000 daily requests for point forecasts and air quality; a separate 30-day trial enables more products. It requires account credentials and suitable key handling. TrueCast has not signed up, purchased anything or embedded a private key.

## What “most accurate” would require

Test representative locations in the user's actual region across weeks and weather regimes. Archive predictions when issued, aligned by valid time and lead time (for example 0–6, 6–24 and 24–72 hours). Compare with independent quality-controlled observations, accounting for station distance, elevation and coverage. Report temperature MAE/bias, precipitation probability Brier score/reliability, and event detection/misses at stated thresholds. A rain-amount score needs a compatible gauge accumulation period. Prevent future/revised forecasts or reanalysis from leaking into an archived prediction test.

Same-hour ECMWF/GFS/ICON comparisons show disagreement, not measured accuracy. A nearby station check establishes a recent measured value at that station; it does not validate the whole forecast. No preferred country/city or provider credentials were supplied, so a universal superiority claim would be unsupported.

During live NWS inspection, the Central Park `latest` observation was over 90 minutes old even though its temperature QC flag was valid. This justified a freshness check in addition to QC. The app searches the three nearest returned stations within 50 km, calculates distance from the selected point, accepts only verified temperature with a recognized unit and an observation age of at most 90 minutes, and otherwise explicitly reports unavailable. It does not substitute an old reading for current model conditions.

## Implemented refresh contract

| Resource                            | Open-app checks                                                                                        | Cached fallback and failure behavior                                                                                                                                                                                       |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Forecast                            | Every 10 minutes; recheck on return after at least two minutes; refresh on reconnection/manual request | Same-place data remains visible while fetching. Saved forecast maximum 24 hours. Incomplete responses cannot overwrite good data. A model valid time over 45 minutes old is labeled delayed even after a successful fetch. |
| Air quality                         | Every 15 minutes; return check after 10 minutes; independent request                                   | Saved data maximum one hour; saved category is labeled. Model valid time is separate from retrieval time.                                                                                                                  |
| US local alerts                     | Every two minutes, or every minute when returned warnings exist; return check after 30 seconds         | Failed/offline/overdue checks are unverified, never an all-clear. Non-expired saved records may remain for at most 30 minutes; expired warnings are filtered. Unsupported coverage is explicitly unknown.                  |
| Radar metadata                      | Every five minutes while the map is visible; also on map entry/resume                                  | Frame age updates independently. Preserve a selected past frame where still available, pan/zoom and the prior loaded frame during a quiet update. A failure is labeled. No offline tile downloads.                         |
| US warning map / NHC tropical layer | Two minutes / ten minutes while that layer is visible                                                  | Refresh independently of the main forecast; retain an existing overlay during a check. Failure marks saved data unverified; warnings expire locally.                                                                       |
| Official narrative / station check  | On opening; ten-minute point cache                                                                     | Separate source panels with observed/updated/retrieved times and coverage. Missing/old/unverified observations remain unavailable.                                                                                         |
| Model comparison                    | On opening; 15-minute cache                                                                            | Compare the same epoch hour and identify the model. No fabricated confidence/accuracy score.                                                                                                                               |

A visible-page clock checks which resources are due; it does not issue every API call every tick. Duplicate forecast/AQ/local-alert requests are coalesced. Location changes cancel the old resources and reject late results. Failures use bounded exponential retries and honor HTTP `Retry-After`, including manual refresh. Reconnect/resume events are coalesced. HTTP expiry is used when exposed and relevant; unsupported cross-origin response headers are not assumed accessible.

Forecast selection is kept by its absolute valid timestamp, rather than an offset that changes when the current hour advances. The containing hour is included; DST repeated hours remain distinct and the selected hour shows its timezone abbreviation. Hourly precipitation accumulation is labeled as the hour ending at the timestamp, not a precise future rain-start countdown. Source updates preserve navigation, chart horizon/metric, horizontal scroll, open details, unfinished search input and map position.

## iPhone background behavior and app updates

[WebKit: Meet Web Push](https://webkit.org/blog/12945/meet-web-push/) and [Declarative Web Push](https://webkit.org/blog/16535/meet-declarative-web-push/) require user-visible notifications and explicitly prohibit silent push as background runtime. [MDN PeriodicSyncManager](https://developer.mozilla.org/en-US/docs/Web/API/PeriodicSyncManager) is experimental; the [browser compatibility data](https://github.com/mdn/browser-compat-data/blob/main/api/PeriodicSyncManager.json) reports Safari unsupported, including iOS through its mirrored Safari entry.

TrueCast therefore stops foreground polling while hidden and checks freshness on visibility return, pageshow, focus and reconnection. The browser can suspend it while closed. A static Pages site cannot promise scheduled closed-app refresh, native Live Activities or continuous storm monitoring. A real notification service would require an external backend and visible push, plus appropriate permission and delivery testing.

App-code updates are independent of weather updates. The service worker pre-downloads the complete versioned 14-file shell with HTTP cache bypass, keeps the running version stable, and exposes a completed update for the next startup or More → Check for updates. It does not reload an active session just because a new download finished. Old shell caches are removed only on activation. API responses and map tiles are not captured in the app-shell cache.

## Validation

See [REVIEW.md](REVIEW.md) for the current checks and remaining limits. Deterministic tests cover network failures, rate limiting, invalid payloads, coalescing, offline cache expiry, cancellation, clock/DST behavior, independent polling, quiet UI updates and station QC/freshness. Real-browser service-worker tests cover multiple successive versions, pending-update startup activation, manual activation and offline reopening. Live checks exercise actual forecast, comparison, radar and official feeds. These tests verify behavior and data handling; they are not a meteorological accuracy study or a physical-iPhone certification.
