A valid run must be no more than six hours old, cannot be future-dated and must cover the requested horizon. Tiles use `hrrr::REFD-F{four-digit lead in minutes}-{YYYYMMDDHHmm}`. ## Interaction and refresh

Both is the initial radar mode. Past and Future filter the same absolute-time bar; NOW marks the boundary. The existing history-length setting defaults to six hours. On a fresh load, the latest observation is shown when available; otherwise the first available forecast is shown. Source timestamps, age, observed/model identity and model-run time remain visible.

At most four frame layers are retained, with two frames prefetched near the current frame. A frame must finish loading without tile errors before its time/legend is committed. Playback uses requestAnimationFrame opacity blending between compatible native products, respects reduced motion and keeps its playing state through zoom/pan. Frame advancement waits for movement to settle and tiles to load. This reduces abrupt image changes; it is not optical flow, advection, invented intermediate radar or guaranteed stutter-free rendering on every device/network. Missing tiles retain the last verified image and timestamp.

Chart scrubbing scrolls the hourly icon/temperature/precipitation strip by the same fractional position. Dragging or wheeling that strip selects the matching chart hour, without programmatic scrolling feeding back into another selection.

Weather, current air quality and supported local US alerts revalidate about every ten seconds while visible. A one-second scheduler checks whether each ten-second interval has elapsed; it does not send requests every second. Concurrent requests coalesce; failures and Retry-After delays take priority. Identical weather payloads update freshness without rebuilding cards/charts. Selected valid hours, searches and scroll positions survive checks. Model output and observations retain their actual valid times; fetching does not create new source data. Other spatial products and detailed source tools retain their own publication-aware caches. iOS may suspend a hidden PWA; no closed-app ten-second polling is promised.

## Validation

Seventeen unit scenarios cover refresh, Retry-After, explicit foreground cadence, stale/future model-run rejection, native radar steps and window bounds, forecast timestamps/DST and missing values. Browser suites exercise refresh persistence, hidden/offline recovery, source errors, all future fields, official warnings/tracks, complete 21-file worker upgrades, and live weather/map flows.

New deterministic browser checks cover proportional chart/strip scrolling in both directions, unchanged DOM after ten-second checks, default six-hour past/future bar, explicit HRRR run URLs, simultaneous partially blended frame layers, time advancement through zoom, four-layer cache bounds, missing tiles retaining the previous time, and switching to limited global history without retaining US forecast frames. Synthetic fixtures remain test-only and are excluded from deployment. iPhone-size Chromium checks establish layout behavior; physical Safari/native certification is not claimed.

## 4.1.1 future-playback correction

The DWD WMS advertises a three-hour interval for `TOTPREC06H`, but live GetMap requests for 03:00/09:00/15:00 UTC returned `InvalidDimensionValue` errors while 06:00/12:00/18:00 returned valid PNGs for the same pinned model run. TrueCast now selects the product's actual six-hour frames. The same cadence correction applies to the global radar timeline's ICON fallback.

A live run advanced across the full 72-hour precipitation window and looped while retaining play state through zoom. Regression fixtures reject the advertised but unsupported intermediate times. Browser assertions exercise play advancement, wraparound, zoom continuation and pause rather than relying on slider scrubbing alone. All earlier run/valid-time and image-failure safeguards remain.
